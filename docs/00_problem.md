## Что и когда предсказывает модель (ML problem formulation)

| Вопрос                                     | Ответ                                                                                                                                                        |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Тип задачи                                 | Бинарная классификация                                                                                                                                       |
| Для кого делается один прогноз             | Для одного пассажира из тестовой выборки                                                                                                                     |
| Что является одной строкой                 | (observation_unit:: Один пассажир)                                                                                                                           |
| Что предсказываем                          | (target_definition:: `Survived`: `1` — выжил, `0` — не выжил)                                                                                                |
| Когда модель делает прогноз                | После получения характеристик пассажира из `test.csv`, но до получения истинного значения `Survived`                                                         |
| Данные, доступные модели в момент прогноза | Все разрешённые признаки из `test.csv`; `Survived` модели недоступен. Точный перечень признаков фиксируется в [[docs/01_data.md]] после знакомства с данными |
| Горизонт прогноза                          | Не применимо: задача Kaggle является ретроспективной                                                                                                         |
| Какой результат возвращает модель          | Класс `0` или `1` для каждого `PassengerId`                                                                                                                  |
| Как часто выполняется прогноз              | При формировании каждой submission для Kaggle                                                                                                                |

## Метрика и критерий успеха

- **Основная offline-метрика:** accuracy
- **Почему она соответствует стоимости ошибок:**
Accuracy является официальной метрикой соревнования Kaggle. Каждая неправильная классификация одинаково уменьшает итоговый результат; реальная бизнес-стоимость ошибок в учебном проекте отсутствует
- **Вторичные метрики:** Precision, Recall, F1-sore
- **Бизнес-метрика:**
- **Минимально приемлемое значение:** 90% для меня будет хорошим результатом
- **Target value / желаемое значение:** 95%

## Ограничения

- **Latency:** строгого ограничения нет; предсказания формируются пакетно для submission.
- **Стоимость inference:** модель должна обучаться и выполнять предсказания на личном компьютере без платной инфраструктуры.
- **Объём данных:** ограничен файлами соревнования Kaggle; точные размеры фиксируются в [[docs/01_data.md]].
- **Интерпретируемость:** желательна для обучения и анализа ошибок, но не является официальным критерием Kaggle.
- **Privacy / compliance:** используются только данные, разрешённые правилами соревнования; учётные данные и токены Kaggle не сохраняются в репозитории.
- **Доступная инфраструктура:** локальный компьютер, Python, Jupyter Notebook, Git/GitHub и Kaggle.
- **Срок:** 10 дней
